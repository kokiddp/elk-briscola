# Project audit — 2026-05-20

Consolidated findings from a three-agent review of the whole repo (backend / frontend / cross-cutting + ops). Use this as a punch list — check items off as they ship. Each finding cites a `path:line` so the offending code is one click away.

Severity legend: **Critical** = correctness or security; do not ship without. **High** = real bug or perf hotspot; fix soon. **Medium** = best practice with concrete impact. **Low** = nice-to-have.

---

## Critical

- [x] **C1 — Optimistic-concurrency races.** *Fixed.* `GameConfiguration` now marks `Version` `IsConcurrencyToken()`, so EF emits `WHERE Version = @old` on every UPDATE and the loser raises `DbUpdateConcurrencyException`. `EfGameRepository.UpdateAsync` already returns `false` on that exception → existing application-level retry kicks in. `RefreshTokenConfiguration` marks `RevokedAt` `IsConcurrencyToken()`; `RotateAsync` catches the exception and returns `RefreshFailureReason.Reuse`, rolling back the staged INSERT of the new child. No schema migration — the flag is EF-side only. All 2389 backend + 10 E2E green.

- [x] **C2 — `.env` ships `ASPNETCORE_ENVIRONMENT=Stress`.** *Fixed in [c2-env-stress-line](#).* Local `.env` line removed (file is gitignored — committing the redaction would have no effect on what's in source control); `.env.example` carries a permanent inline warning so the next maintainer to copy it gets the message.

- [x] **C3 — JWT leaks via Serilog request logs.** *Fixed.* `OnMessageReceived` now scrubs `access_token=...` from `ctx.Request.QueryString` immediately after consuming it, so any downstream logger that surfaces the URL (today or via a future enrich-with-query-string change) sees `access_token=<redacted>` instead of the bearer JWT. Also set `JwtBearerOptions.IncludeErrorDetails = env.IsDevelopment()` so the WWW-Authenticate `error_description` on 401 doesn't echo the inner validation exception in Production. Verified with the existing 134-test backend integration suite.

- [x] **C4 — CORS default-open in Production.** *Fixed.* `Program.cs` now throws `InvalidOperationException` at startup if `Cors:AllowedOrigins` is empty and `Environment.IsProduction()`. Dev / Stress / Test keep the AllowAnyOrigin fallback so local stacks still work.

- [x] **C5 — PlayCard publish/append ordering.** *Fixed.* `IGameRepository.UpdateAndAppendMoveAsync` now commits the snapshot bump and the move-log row in one EF transaction; `GameRoom.PersistStateAndAppendMoveAsync` is the only path used from `PlayCardAsync` + `ForfeitAsync`. The old standalone `PersistStateAsync` was deleted. As a bonus, the per-move DI-scope count drops from 2 → 1 (partially eats **H8**). All 2389 backend tests + 10 E2E green.

## High

### Concurrency / data integrity

- [x] **H1 — `HubMethodRateLimiter` is per-connection.** *Fixed.* Rebuilt as a DI singleton keyed by `(userId, method)`; `GameHub.TryAcquireRateLimit` routes `Context.UserIdentifier` into the bucket lookup. Buckets are not evicted on disconnect — at ~32 bytes per timestamp × `permitLimit` per bucket, even 100k users × 2 methods stays under ~10 MB. Five unit tests in `HubMethodRateLimiterTests` cover budget consumption, window-slide refill, per-user isolation, the multi-connection-bypass regression, and per-method independence.
- [x] **H2 — No rate limit on `change-password` / `logout`.** *Fixed.* Two new policies `auth-change-password` (5/15min) and `auth-logout` (30/min), both partitioned by user. `appsettings.Stress.json` overrides bump them to 1M/min so the stress harness isn't throttled. Two integration tests cover the 429 transition. Defaults are configurable via `RateLimits:auth-change-password:*`/`RateLimits:auth-logout:*` exactly like the existing policies.
- [x] **H3 — `_idleTimers` mutation safety.** *Documented.* Verified all `ScheduleIdleChecks` / `CancelIdleTimers` call sites are inside `ApplyAsync` (i.e., dispatched through the single-reader channel). Timer fire-callbacks re-enter via `EnqueueAsync` and the next loop iteration handles cleanup — they don't touch the list. Added an XML doc on `_idleTimers` pinning the invariant for the next contributor; a runtime thread-id check would be a false signal because `ProcessLoopAsync` can resume on any thread-pool thread after each `await`.

### Frontend race / lifecycle

- [x] **H4 — `LobbyService` auto-routes from any route.** *Fixed.* The effect now skips `navigateByUrl` when `router.url.startsWith('/game/')`, leaving spectators / mid-match players where they are. We still clear `lastSeenPendingGameId` + `lastStartedGameIdSig` so a subsequent transition can route normally once the user returns to a non-game route. Three new tests cover the lobby→game route, the profile→game route, and the no-op-when-already-on-game-route case.
- [x] **H5 — `GameService` not disconnected on logout.** *Fixed.* Added an `effect` in `GameService.constructor` that calls `disconnect()` whenever `auth.currentUser()` flips to null and a hub connection is open. Mirrors the same pattern in `LobbyService`. Two unit tests cover the disconnect on logout + the no-op when there's nothing to disconnect.
- [x] **H6 — 4p initial snapshot can't latch `mySeatIndex`.** *Verified + tested.* The preferred-path branch in the latch effect already trusts `s.mySeatIndex` when present (line 238); the server's `RedactedStateForUser` always populates it for seated players (see `GameRoom.SnapshotForUser`). The fallback is only reached for spectators or clients that lose `mySeatIndex` somehow. Added a regression test pinning the fresh-4p-deal latch via the preferred path so the table renders immediately on `Joined` rather than waiting for counts to diverge.
- [x] **H7 — `window.prompt()` for private-game password.** *Fixed.* New `JoinPasswordDialogComponent` (standalone, reactive-form-driven, styled like the existing CreateGameDialog) replaces the blocking `prompt()`. `LobbyComponent.onJoin` now opens the modal for private games; `onPasswordSubmitted` / `onPasswordCancelled` route the resolution. Two unit tests cover the submit + cancel flows.

### Performance

- [x] **H8 — Per-move N×2 DI-scope creation.** *Partially fixed via C5.* `PlayCard` + `Forfeit` paths now use `PersistStateAndAppendMoveAsync` → one scope, one transaction. Disconnect / Reconnect still call standalone `AppendMoveAsync` but those are off the hot path.
- [x] **H9 — `OpenLobbyJanitor` filters in-memory.** *Fixed.* New `IGameRepository.ListExpiredOpenAsync(cutoff, take)` pushes the `Status == Open AND CreatedAt < cutoff` predicate into SQL (uses the existing `IX_Games_Status` + `IX_Games_CreatedAt` indexes). The janitor now also caps at 500 per tick so a backlog can't fan out unbounded — the next tick picks up any leftover. Two new unit tests pin the cutoff filter + the cap behavior.
- [x] **H10 — `RankingService.LoadManyAsync` is N×1 await.** *Fixed.* `IRankingRepository.GetManyAsync(IEnumerable<Guid>)` returns a single-round-trip dict; `LoadManyAsync` now uses it and preserves input ordering for the per-seat outcome walk. EF impl dedups inputs and seeds 1500-Elo defaults for missing rows in one `SaveChanges`. New unit test pins the dedup + default-seeding contract.
- [x] **H11 — Refresh-token chain revocation N+1.** *Fixed.* `RevokeDescendantsAsync` now loads every token belonging to the affected user in one SQL round-trip, then walks the `(Id → ReplacedByTokenId)` chain in memory. Added a 64-hop cap as defense-in-depth against malformed chains (the seen-set already catches cycles). Existing `Reusing_a_revoked_token_returns_Reuse_and_revokes_chain` integration test still passes — same semantics, single round-trip.

### Ops / edge

- [x] **H12 — SPA serves no security headers.** *Fixed.* `frontend/nginx.conf` now emits CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Cross-Origin-Opener-Policy, and Permissions-Policy at the edge — both on bare `/` and on SPA deep-link routes (the `location = /index.html` block had to repeat them because nginx's `add_header` inheritance is suppressed once an inner block defines any). CSP keeps `'unsafe-inline'` on script-src + style-src because Angular's Critters optimization emits an inline `onload` handler on the async-loaded stylesheet link; everything else (img, font, connect, frame-ancestors, base-uri, form-action) is locked down. Two new E2E tests in `security-headers.spec.ts` pin the contract.
- [x] **H13 — Mutable image tags everywhere.** *Fixed.* All five base images pinned by SHA-256 digest in the prod compose + Dockerfiles: `postgres:17-alpine@sha256:9794…`, `node:22-alpine@sha256:b235…`, `nginx:alpine@sha256:8491…`, `mcr.microsoft.com/dotnet/sdk:10.0@sha256:dc84…`, `mcr.microsoft.com/dotnet/aspnet:10.0-noble-chiseled-extra@sha256:f923…`. The dev compose keeps the floating tag so contributors get fresh patches without manual digest bumps. Build + 12 E2E green against the pinned set.
- [x] **H14 — `docs/api.md:35` lies about `/auth/register`.** *Fixed.* Doc updated to describe the real `201` + `{ id, username }` + `Location` shape, with a note that the client must follow up with `/auth/login`. Also added rows for `change-password` and `logout` policies. New integration test pins the response shape so future drift fails the build.
- [x] **H15 — `backend/src/Briscola.Api/logs/` is in the working tree.** *Fixed.* Cleaned the stale rolling-file logs from the local working tree + added `**/logs/` to `.gitignore` so the directory itself can't get committed as an empty placeholder. The pre-existing `*.log` glob already excluded the file contents.

## Medium

- [x] **M1 — `Program.cs:266-270` runs `HydrateAsync` unconditionally.** *Fixed.* Wrapped in a `SchemaReadyAsync` probe that checks `CanConnectAsync` + `GetAppliedMigrationsAsync`. With `Migrations:RunOnStartup=false` and no schema, the orchestrator boots empty and a warning is logged instead of the host crashing.
- [x] **M2 — `EfRankingRepository.MarkProcessedGameAsync` SELECT-then-INSERT race.** *Fixed.* Now stages the INSERT first and catches `DbUpdateException`. The catch path re-checks via `AsNoTracking().AnyAsync()` and detaches the conflicted entity; if the row really wasn't already present we rethrow (so an FK violation or DB connectivity failure isn't silently swallowed).
- [x] **M3 — `MeController.Patch` doesn't validate `activeCardSetId`.** *Fixed.* The controller now injects `ICardSetCatalog` and returns 400 `UnknownCardSet` when the requested id isn't in the catalog. Two new integration tests: known-id ✓, unknown-id → 400.
- [x] **M4 — `GameEventDispatcher` seat-players cache eviction.** *Fixed.* `LobbyGameUpdated` now evicts the per-game seat-players cache (any seat change pre-start invalidates the snapshot), and `LobbyGameEnded` evicts too as belt-and-suspenders for the janitor / lone-leaver abandon path that doesn't emit a separate `GameFinished`.
- [x] **M5 — `core/error-toast.service.ts` toast timer leak.** *Fixed.* The service now tracks the `setTimeout` handle per toast and clears it in `dismiss(id)` + `clear()`, so manual dismisses don't leave orphaned timers in the queue.
- [x] **M6 — Multiple 1s `setInterval` clocks.** *Fixed.* New `ClockService` (`providedIn: 'root'`) exposes a `now` signal driven by a single 1Hz interval that's reference-counted via `subscribe()`. `OpponentAreaComponent`, `ReconnectBannerComponent`, and `GameTablePageComponent` all switched over — the interval runs only while at least one consumer has an active deadline to count down to, and idle pages (lobby, profile) pay nothing. 4 new spec cases pin the contract.
- [x] **M7 — `AuthController` username-enumeration timing oracle.** *Fixed.* Login now runs `PasswordHasher.VerifyHashedPassword` against a lazy-initialized sentinel PBKDF2 hash on the user-not-found branch, so the latency matches the happy path's verify. An attacker can no longer distinguish "no such user" from "wrong password" by timing.
- [x] **M8 — `docker-compose.dev.yml` Postgres bind.** *Fixed.* Switched the port mapping to `127.0.0.1:5432:5432` so anyone on the same network can't hit the dev DB with its weak default password.
- [x] **M9 — Container hardening on prod compose.** *Fixed.* The `api` service drops all capabilities, runs `read_only: true` with a `/tmp` tmpfs, and applies `no-new-privileges`. The `frontend` service can't take the full set (the nginx:alpine entrypoint chowns its cache dirs before dropping privileges, which read-only + cap_drop break), so it keeps `no-new-privileges` only — documented inline. 12 E2E green against the hardened set.
- [x] **M10 — E2E workflow misses Docker Buildx cache.** *Fixed.* `.github/workflows/e2e.yml` now sets up `docker/setup-buildx-action` and builds via `buildx bake` with `cache-from`/`cache-to` pointed at `type=gha` (scope `elk-briscola`). The subsequent `docker compose up` re-uses the loaded images. Should shave ~5–8 min per warm-cache PR.
- [x] **M11 — `backend.yml` vuln-scan step swallows `dotnet list` failures.** *Fixed.* Removed `|| true` so a crashed scan now fails the build instead of looking clean. Added `set -euo pipefail` to the same block to catch any other failed command in the chain. `docs/security.md` already documented the correct intent — the bug was in CI, not the doc.

## Low / coverage gaps

- [x] **L1 — No spec on `top-nav.component.ts`.** *Fixed.* New `top-nav.component.spec.ts` covers the auth-gated visibility branch, the resume-pill render/href on a running game, and the no-render-when-not-running case. (game-table-page already has spec coverage — verified.)
- [x] **L2 — No test for the EF concurrency race, the rate-limit-per-user bypass, or the dispatcher cache eviction.** *Covered.* Added in C1 (concurrency token + retry path), H1 (per-user limiter regression), and M4 (lobby-update eviction).
- [x] **L3 — `correlation-id.interceptor` Math.random hex space.** *Fixed.* Switched to per-nibble construction so each segment spans the full hex alphabet uniformly regardless of length.
- [x] **L4 — End-game-dialog team Elo divides.** *Cleaned up.* Extracted a `teamElo(a, b)` helper that does one divide per team and threads the null-guards through one branch.
- [x] **L5 — `my-hand.component.html` hardcoded Italian.** *Fixed.* Now uses a new `game.card.ariaLabel` key with `{rank}` + `{suit}` interpolation (en: "{rank} of {suit}", it: "{rank} di {suit}").
- [ ] **L6 — `InMemoryGameEventBus` unbounded channel.** *Deferred.* The current scale doesn't justify bounded backpressure, and switching to `FullMode.Wait` would couple producer latency to the slowest hub consumer. Leaving as a known design choice.
- [ ] **L7 — `AuthController.Login`** does two queries when email contains `@`. *Deferred.* The two-query path runs at most 5 times/min/IP (rate limit). A single OR-shaped EF query would be a Phase-2 refactor; the time savings don't justify the change today.
- [x] **L8 — `SystemTimerService` swallows callback exceptions.** *Fixed.* `TimerRegistration.FireAsync` now wraps the callback in a try/catch and logs at Error via `LoggerMessage`. Operators get a signal when an idle-tick fire faulted.
- [x] **L9 — `GameRoom.ProcessLoopAsync` hydrate poison.** *Fixed.* Wrapped the hydrate in a try/catch that fails the channel (`TryComplete(ex)`) and propagates the exception to every queued + future caller. No more silent hangs on `EnqueueAsync.completion.Task`.
- [x] **L10 — `LobbyService.JoinAsync` ordering.** *Fixed.* Idempotent already-seated check now runs BEFORE `ValidatePrivateGame`, so a re-seated caller without their password gets a no-op return instead of `InvalidPassword`. New unit test pins the behavior.
