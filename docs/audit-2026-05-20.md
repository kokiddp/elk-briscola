# Project audit — 2026-05-20

Consolidated findings from a three-agent review of the whole repo (backend / frontend / cross-cutting + ops). Use this as a punch list — check items off as they ship. Each finding cites a `path:line` so the offending code is one click away.

Severity legend: **Critical** = correctness or security; do not ship without. **High** = real bug or perf hotspot; fix soon. **Medium** = best practice with concrete impact. **Low** = nice-to-have.

---

## Critical

- [ ] **C1 — Optimistic-concurrency races.** `backend/src/Briscola.Infrastructure/Persistence/Configurations/GameConfiguration.cs:26-27` opts out of `IsConcurrencyToken()` on `GameRecord.Version`. `EfGameRepository.UpdateAsync:45-113` then does a read-modify-write at default Postgres Read-Committed isolation, so two concurrent `JoinAsync`/`LeaveAsync` racers can both observe v=N and both write v=N+1. The `MaxJoinRetries=3` loop hides it most of the time but does not fix it. Same shape on `RefreshTokenEntity` (no Version at all): `RefreshTokenService.RotateAsync` can be raced into producing two valid children of one parent. **Fix:** mark `Version` `IsConcurrencyToken()`; switch refresh-token rotation to a conditional `UPDATE … WHERE Id = @id AND RevokedAt IS NULL` checked by rows-affected.

- [x] **C2 — `.env` ships `ASPNETCORE_ENVIRONMENT=Stress`.** *Fixed in [c2-env-stress-line](#).* Local `.env` line removed (file is gitignored — committing the redaction would have no effect on what's in source control); `.env.example` carries a permanent inline warning so the next maintainer to copy it gets the message.

- [x] **C3 — JWT leaks via Serilog request logs.** *Fixed.* `OnMessageReceived` now scrubs `access_token=...` from `ctx.Request.QueryString` immediately after consuming it, so any downstream logger that surfaces the URL (today or via a future enrich-with-query-string change) sees `access_token=<redacted>` instead of the bearer JWT. Also set `JwtBearerOptions.IncludeErrorDetails = env.IsDevelopment()` so the WWW-Authenticate `error_description` on 401 doesn't echo the inner validation exception in Production. Verified with the existing 134-test backend integration suite.

- [x] **C4 — CORS default-open in Production.** *Fixed.* `Program.cs` now throws `InvalidOperationException` at startup if `Cors:AllowedOrigins` is empty and `Environment.IsProduction()`. Dev / Stress / Test keep the AllowAnyOrigin fallback so local stacks still work.

- [x] **C5 — PlayCard publish/append ordering.** *Fixed.* `IGameRepository.UpdateAndAppendMoveAsync` now commits the snapshot bump and the move-log row in one EF transaction; `GameRoom.PersistStateAndAppendMoveAsync` is the only path used from `PlayCardAsync` + `ForfeitAsync`. The old standalone `PersistStateAsync` was deleted. As a bonus, the per-move DI-scope count drops from 2 → 1 (partially eats **H8**). All 2389 backend tests + 10 E2E green.

## High

### Concurrency / data integrity

- [ ] **H1 — `HubMethodRateLimiter` is per-connection** (`backend/src/Briscola.Api/Hubs/Limits/HubMethodRateLimiter.cs`). N WebSockets under one user → N× the `PlayCard` / `SendChat` budget. Partition by `Context.UserIdentifier`.
- [ ] **H2 — No rate limit on `change-password` / `logout`** (`Controllers/AuthController.cs:163, 184`). Brute-forcing the current password against a stolen access token is uncapped. Apply a partitioned-by-user policy.
- [ ] **H3 — `_idleTimers` mutation safety** (`GameRoom.cs:33, 560-583`). List is mutated from the room loop AND from timer fire-callbacks. Today's call order is safe by accident; one extra caller flips it into a bug. Document or guard with the channel.

### Frontend race / lifecycle

- [ ] **H4 — `LobbyService` auto-routes from any route** (`features/lobby/lobby.service.ts:56-66`). When `pendingGameId === lastStartedGameId`, the service yanks the user with `navigateByUrl` regardless of where they are. Gate on `!router.url.startsWith('/game/')`.
- [ ] **H5 — `GameService` not disconnected on logout.** `AuthService.logout()` clears auth but the game `HubConnection` keeps running with a revoked token. Mirror the auth-effect that `LobbyService` already has.
- [ ] **H6 — 4p initial snapshot can't latch `mySeatIndex`** (`game-table-page.component.ts:228-261`). Fallback heuristic only fires when one seat matches `myHand.length`; on a fresh 4p deal everyone has 3 cards so it never latches, and the table renders empty until counts diverge. Trust `s.mySeatIndex` from the wire if present.
- [ ] **H7 — `window.prompt()` for private-game password** (`features/lobby/lobby.component.ts:115-122`). Blocks JS, untestable, deprecated in cross-origin iframes. Use a modal.

### Performance

- [x] **H8 — Per-move N×2 DI-scope creation.** *Partially fixed via C5.* `PlayCard` + `Forfeit` paths now use `PersistStateAndAppendMoveAsync` → one scope, one transaction. Disconnect / Reconnect still call standalone `AppendMoveAsync` but those are off the hot path.
- [ ] **H9 — `OpenLobbyJanitor` filters in-memory** (`Background/OpenLobbyJanitor.cs:33`). `Where(r => r.CreatedAt < cutoff)` runs after materialising every open row. Push the predicate into SQL.
- [ ] **H10 — `RankingService.LoadManyAsync` is N×1 await** (`Application/Ranking/RankingService.cs:98-107`). 4 sequential lookups per 4p finish. Add a bulk `GetManyAsync`.
- [ ] **H11 — Refresh-token chain revocation N+1** (`Infrastructure/Auth/RefreshTokenService.cs:125-159`). CTE or in-memory walk.

### Ops / edge

- [ ] **H12 — SPA serves no security headers.** `frontend/nginx.conf:168` serves `index.html` direct, bypassing the backend's `SecurityHeadersMiddleware`. CSP / X-Content-Type-Options / Referrer-Policy belong at the edge.
- [ ] **H13 — Mutable image tags everywhere.** `postgres:17-alpine`, `aspnet:10.0-noble-chiseled-extra`, etc. Pin by digest in the prod compose + Dockerfiles.
- [ ] **H14 — `docs/api.md:35` lies about `/auth/register`.** Doc claims it returns `{ accessToken, refreshToken, expiresAt }`; real handler returns `201` with `{ id, username }` + `Location`. Doc-vs-code drift; clients break.
- [ ] **H15 — `backend/src/Briscola.Api/logs/` is in the working tree.** `.gitignore` covers `*.log` but the dir leaks into clones.

## Medium

- [ ] **M1 — `Program.cs:266-270` runs `HydrateAsync` unconditionally** — crashes startup if `Migrations:RunOnStartup=false` and the DB isn't pre-migrated. Gate behind the same flag.
- [ ] **M2 — `EfRankingRepository.MarkProcessedGameAsync:60-72` SELECT-then-INSERT race.** Switch to INSERT-then-catch-`DbUpdateException`.
- [ ] **M3 — `MeController.Patch:85-89` doesn't validate `activeCardSetId`** against `ICardSetCatalog`. Bad ids get embedded as JWT claims.
- [ ] **M4 — `GameEventDispatcher` seat-players cache** (`Hubs/GameEventDispatcher.cs:161-187`) has no `LobbyGameUpdated` eviction. Fragile if a future caller hits it pre-start.
- [ ] **M5 — `core/error-toast.service.ts:23-25`** never clears the auto-dismiss `setTimeout` when manually dismissed → unbounded timer set on long sessions.
- [ ] **M6 — Multiple 1s `setInterval` clocks** in `OpponentArea`, `ReconnectBanner`, `GameTablePage`. Lift to a shared `ClockService`.
- [ ] **M7 — `AuthController.ResolveAsync:212-226` username-enumeration timing oracle.** Two queries when input contains `@`; `CheckPasswordAsync` only on hit. Always run a dummy hash on miss.
- [ ] **M8 — `docker-compose.dev.yml:24` binds Postgres to `0.0.0.0:5432`** with `briscola-dev` password. Bind to `127.0.0.1`.
- [ ] **M9 — No `cap_drop: [ALL]` / `read_only: true` / `tmpfs: /tmp`** on prod compose services.
- [ ] **M10 — E2E workflow misses Docker Buildx cache** (`cache-from: type=gha`). ~5–8 min wasted per PR.
- [ ] **M11 — `docs/security.md:53` describes the vuln-scan step incorrectly.** `backend.yml` pipes through `|| true` and greps; a crashed `dotnet list` silently passes.
